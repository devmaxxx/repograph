# 0.6.0 — every language we write, measured before and after: design

Date: 2026-09-11. Base: `main` at `b21fb0f`, tagged `v0.5.0`. Nothing in this document is
implemented. It replaces the Kotlin-only draft of the same day (`e389b24`, called "the Kotlin draft"
below): Max's instruction is that 0.6.0
supports every development language in Bonliva's repositories and his own. The plans that execute
it are listed in §7; the gates in §6 are copied, unedited, into the release's results document
before any of them is read.

## What 0.6.0 is, and what it is not

Four pieces of work, in this order:

1. **The measurement debt 0.5.0 left** (§1). Six gates are written and unread, and two of them are
   the baseline and the instrument every language reading is judged against.
2. **A language layer** (§3): a file picks its grammar through one table, a reference between symbols is
   walked like a call, a file no grammar reads is
   a file and nothing else, each language family resolves names through its own resolver, and two
   languages embedded in markup are read by blanking.
3. **Every language the census in §0 finds** (§4), each on its own corpus under G6's gate, with
   employer code's cases kept outside this public repository (§5).
4. **A release procedure that cannot lose its run to `[skip ci]` again** (§8).

The graph does not change shape. No node or edge kind is added; every language writes the kinds
TypeScript already writes, so `impact`, `trace`, `changes` and `ask` read it without a new code path.

## 1 · The measurement debt, and why it goes first

Six gates are written and unread. Each is named in §10 of
`docs/bench/2026-09-10-next-version-levers-results.md` and in its ledger section. None needs a line
of product code. Every one needs the one writable worktree, `~/bench/beauty-crm-test`, reset by
`bench/probe/reset.sh`; G23 also needs a machine `bench/probe/quiet.sh` accepts.

| gap | what is unread | needs | price |
|---|---|---|---|
| G23 | the control: the same binary through `readers.sh` twice, inside the wall and RSS bars, and the `avg_cpu` spread | a quiet machine: on power, `quiet.sh` passing | one suite run twice, no tokens |
| G15 | the four recorded arms re-run, `anchors/<kind>` totals recorded through `bench/history/track.py` | the worktree | four `bench` runs, no tokens |
| G39 | Task 6: `graph.json` growth under the generic grammar, the one-file `update` wall, `graphdiff.py` against `main`'s build | a corpus build in the worktree | one build, no tokens |
| G34 | the corpus half: the bench line's `families=` clause on a corpus build | the same build as G39 | nothing extra |
| G32 | the fixture copy rebuilt, `enrich` run, the before and after arms read | the worktree | ≈ $0.20 of haiku |
| G19 | the embed cadence clauses on the small model | the worktree, `embed.sh` | one whole-store embed, ≈ 4.5 minutes |

One reading is added that no ledger section owns. **B0** is the blast suite on both corpora —
`bench/blast.jsonl` and `bench/corpora/beauty-crm-mobile/blast.jsonl` — run through
`bench/compare/run.py` with the `v0.5.0` binary, on the same day and the same machine as every
language reading after it. The last blast result files are from 2026-09-04 and a different binary;
the language gates below are stated against B0 and not against them.

**Why this is ahead of the languages and not beside them.** Every language puts new nodes into
every list `ask` fuses — Kotlin's comments alone cite `FR-VIS-47`, `ADR-022` and more, so the id references move too — and the
four recorded arms can move the day one lands. A move can only be judged against a baseline read on
the same machine, with the same instrument, before the change. G15 and B0 are that baseline, and
G23 is what says a reader-row difference is a difference and not the machine. Read after Kotlin,
all three would be measuring the change they are meant to judge.

**Order inside the debt.** G23 first, because every later reader number is judged through its bars.
G15, G39, G34 and B0 share one reset and run next. G32 spends money and runs after the free
readings. G19 runs last and blocks nothing.

**Where it stops.** If `quiet.sh` refuses the machine three sittings running, G23 is recorded as
unread, the bars stay the 2026-09-07 ones, and the languages proceed judged on counts alone, which do not
depend on machine noise. Its cost rows are then reported and not gated, and the results document
says so.

**A hand walk, not tag queries**, for every language, for the reason the Kotlin draft gave: a tags
query yields definitions and nothing else — no `Extends`, no visibility, not the declared type of a
field the calls pass resolves a receiver through.

**Node names are pinned by a dump, not by this document.** `dump_tree` (`src/code/cases.rs:548`)
picks its grammar through `Lang::of` once L2 lands, so a dump of any construct prints the real shape
before a case is written against it. The scratch crate's `gcensus dump <lang> <file>` does the same
today and was used while planning.

**The risk is Windows.** None of the thirteen crates' own workflow files names Windows (read
2026-09-11); the tree-sitter org's grammars run shared workflows that were not inspected. This
repository's CI builds on `windows-latest` and `release.yml` can be dispatched from a branch to build
all three targets without publishing. Both are gates, per grammar: the grammar lands in the PR that
adds its walk, so a grammar that fails MSVC fails its own PR and nothing else.

## 3 · The language layer

### L1 · A file with no grammar gets a file node and nothing else

Unchanged from the Kotlin draft's K1. `language_for` (`src/code/symbols.rs:9-15`) picks the TSX
grammar for `.tsx` and the TypeScript grammar for everything else, so a repository globbing `**/*.cs`
today gets C# parsed as TypeScript: a normal-looking file node, wrong or missing symbols, no warning.
Tree-sitter returns a tree for any input, so the fallback at `symbols.rs:177` never runs, and the
three passes (`symbols.rs:177`, `calls.rs:163`, `idrefs.rs:62`) each carry the mistake.
`language_for` becomes `Lang::of(rel) -> Option<Lang>`; a globbed file whose extension has no grammar
gets one `File` node, and `build` names the extensions it indexed as files only, on stderr, once. The
JavaScript family keeps the TypeScript grammar. It lands first and alone: it is a defect on `main`.

### L2 · One table picks the grammar; one module per language

`src/code/lang.rs` holds `Lang`, one variant per grammar in §2 plus `Razor` and `Vue`, and
`Lang::of(rel)` is the only place a file name picks one. Each new language lives in
`src/code/<lang>/` and exposes `extract(ctx: &Resolver, rel: &str, source: &str) -> Extraction`,
parsing once per file and writing into the same `Extraction` TypeScript writes.
`CodeExtractor::extract` dispatches on `Lang`. The TypeScript path keeps its three parses: a refactor
nothing measured is not in this release.

### L3 · Resolvers by family

`Resolver::new` (`src/code/imports.rs:81`) already walks the repository once for `tsconfig.json` and
`package.json`. The same walk collects what each family needs, and only for families whose
extensions `code_globs` reaches. Two kinds of family:

- **Path-resolved** — the importer names a file or a directory: TypeScript (as today), Rust (module
  tree), Python (module path), Dart (`package:` and relative URIs), Bicep (`module` paths), HCL
  (`source` and the directory as module), Shell (`source` paths). These go stale as TypeScript does
  today, with two exceptions whose names resolve without an import naming the file: `update`
  re-reads every script sourcing a changed or removed one, and every `.tf` file of a directory whose
  `.tf` file changed or went, with every file whose module call imports that directory.
- **Name-indexed** — the importer names a qualified name, and the file declaring it is not named after
  it: JVM (Kotlin and Java share one index, `package.Name`), .NET (C# and Razor, `Namespace.Type`),
  SQL (object names), GraphQL (fragment and type names). The walk reads each file's header — package
  or namespace lines and top-level declared names — into a map from qualified name to every file
  declaring it; a name declared by several files (Kotlin `expect`/`actual`, a C# `partial` type, a
  table altered by many migrations) resolves to all of them, each keeping its own id.

**The staleness rule for an indexed family**, generalised from K3: on `update`, when a file of the
family is added or removed, or a changed file's header — its package or namespace lines and its
top-level declared names — differs from the `Declares` edges the graph holds for it, every file of
that family joins the stale set before `apply_diff`'s co-declared closure runs. A header also
carries its directives — C# `using` and `global using`, an `_Imports.razor` `@using` — which change
what a file resolves without declaring anything; they are compared like the rest and never enter the
index. The previous headers are kept in `.repograph/headers.json`, one entry per indexed file: the graph records no package
or namespace, so the headers a change is compared against have to be stored. A body-only edit, the
common case, re-reads that file alone. The price is bounded by the family's file count — 1,194 C#
files is the largest — and paid only when a declaration appears, disappears or moves; the one-file
update is a cost row per family (§6), so the price is read rather than assumed.

### L4 · Nested members keep their container

Unchanged from K4: `impact::container` (`src/impact.rs:71`) splits at the last `.`, not the first, so
`Outer.Inner.method` is changed through `Outer.Inner`. C# nested types, Rust `impl` members of nested
modules' types, SQL members of schema-qualified tables and GraphQL fields all rely on it.

**`.` means member, and nothing else does.** Where a language's own address uses dots — a Terraform
`aws_instance.web`, a PostgreSQL `app.clients` — the id joins those segments with `/`
(`sym:<rel>::aws_instance/web`, `sym:<rel>::app/clients`), and a member follows with `.`
(`app/clients.status`). A test pins `impact::bare` and `container` on such an id.

### L5 · The grammar generation moves once

`walk::GRAMMAR` (`src/walk.rs:29`) goes from 1 to 2 in the PR that turns the defaults on (L7), not
once per language: a 0.5.0 store re-reads the tree one time, on the path `tests/grammar.rs` covers.

### L6 · Embedded languages are read by blanking

Razor's `@code { … }` and `@functions { … }` blocks are C#, and a Vue file's `<script>` block is
TypeScript. Neither has a usable grammar (§2). The file is copied with every byte outside the embedded
blocks replaced by a space, newlines kept, and the directive bytes that open a block overwritten with
a same-length wrapper — `@code {` becomes `class X {` padded inside the directive's own bytes where it
fits, or the block is wrapped on the directive's line otherwise — so every row and column in the
blanked copy is the row and column in the file and no offset table exists. The census in §0 read 40
of 41 Razor blocks and all 8 Vue scripts clean this way. `bench/compare/truth.py` already blanks
source this way for its readers.

### L7 · Every language is on by default

`Config::default().code_globs` (`src/config.rs:69`) gains every extension a grammar or L6 reads, and
this repository's `repograph.toml` follows. A repository with none of them sees no difference. The JavaScript
family stays out of the defaults, as it is today: it is not a new language, and a default `**/*.js`
would read bundled output. If the
retrieval rule (§6) fails while a language's blast gates pass, that language leaves the defaults — the
one whose removal restores the rule, tried in descending order of nodes it added — ships behind an
explicit glob, and the README says so. `REPOGRAPH_CODE_GLOBS`, whitespace-separated, overrides
`code_globs` for one process: it is how a reading withdraws a language without writing `repograph.toml`
into a corpus, and it is documented beside `code_globs`.

### L8 · Attributes point at declarations, never at a shared name

TypeScript writes `DecoratedBy` to `deco:<Name>`, a node every decorated file shares. A new language
does not: a C# `[HttpGet]` on 3,975 attribute lines, a Rust `#[derive(Debug)]` or a Kotlin
`@Serializable` shared as one node would put nearly every file of the language into `apply_diff`'s
co-declared closure (`src/main.rs:213-226`) on every update, and an attribute declared outside the
repository names no code `impact` can walk to. So an attribute, annotation, decorator or derive writes
`DecoratedBy` to the declaring symbol's id when the name resolves in the repository, and nothing
otherwise. This changes the Kotlin draft's `anno:<Name>` rule, for this reason.

### L9 · Generated code is code

Tracked generated files are read like any other: the 395-file C# API client and the two GraphQL
schemas are what the rest of the code calls. A user who wants them out excludes them by glob.

### L10 · No edge crosses a language family

Kotlin and Java meet in one index, and so do C# and Razor, because each pair compiles together. No
edge joins families: TypeScript reaches SQL through query builders in 424 files and GraphQL through
codegen constants in 187, and the Kotlin draft's K6 found TypeScript and Kotlin meeting only through
generated OpenAPI clients. A contract or codegen edge is a design of its own.

### L11 · A reference between symbols is walked like a call

`impact` walks `Calls` and `Extends` (`src/impact.rs:8`), plus imports, re-exports and member
declarations; a `References` edge is read only by `ask`'s expansion (`src/query.rs:21`), because
until now every `References` edge pointed from code or a document at a requirement id, an entity or a
file. The new languages write `References` between symbols — a migration altering a table, a
GraphQL field naming a type, a Rust `impl` in another file, a Terraform expression naming a
resource — and `impact`, `trace` and `changes` would never see them. So a `References` edge whose
target is a `sym:` id is walked as a call is; one whose target is anything else is not. No
TypeScript extractor writes a `References` edge to a `sym:` id today, so TypeScript's blast output does
not move, and the master plan's L-task proves it on B0's cases before any language lands.

## 4 · The languages

Each section says what becomes a node and an edge, how names resolve, and every deliberate difference
from TypeScript with its reason. Node kinds are pinned by dumps in the plans. Ids follow the shipped
format: `sym:<rel>::<Name>` for a top-level declaration, `sym:<rel>::<Container>.<member>` below it.
Overloads and repeated declarations collapse through `CodeExtractor::extract`'s dedup, as TypeScript
overloads do. Generic parameters are not part of a name.

### Kotlin

The Kotlin draft's K2, K3 and K6 stand, with L8 replacing its `anno:` rule: classes, interfaces,
`fun interface`, enums, data, sealed and annotation classes, objects; top-level `fun`, `val`, `var`,
`typealias` and extension functions named without their receiver; members, constructor `val`s and
companion members as `Class.member`; nested declarations; `Extends` from the delegation specifiers;
`Calls` through locals, same-package and imported names, typed properties and objects; `Imports`
through the JVM index. Public by default: `private` and `protected` are not exported, `internal` is.
`.gradle.kts` scripts are not read. Corpus: `beauty-crm` `mobile/`.

### Java

Classes, interfaces, enums, records and annotation types; methods, fields and constructors as
`Type.member`; nested types. `extends` and `implements` write `Extends`. `import a.b.C`, `import a.b.*`
and `import static a.b.C.m` resolve through the JVM index Kotlin builds, so a Kotlin file importing a
Java class resolves and the reverse. `Calls` through locals, fields with a declared type,
`this.x.m()`, and `Type.m()` on a static. Only `public` is exported: Java's default is package access,
and a package is not a file. Corpus: `bonliva-consultant-portal`'s Android shell (private).

### C#

Namespaces, file-scoped and block, are headers for the .NET index and not nodes. Classes, records,
structs, interfaces, enums and delegates are symbols; methods, properties, fields, events,
constructors and primary-constructor parameters are `Type.member`; nested types are `Outer.Inner`.
The base list writes `Extends` for base class and interfaces alike.

- **`partial`.** Each file declaring part of a type writes its own `sym:<rel>::Type`, and a name
  resolves to every declaring file, as `expect`/`actual` does. 179 files hold a partial type.
- **Name resolution.** The enclosing type, then each enclosing namespace outward, then `using N;`,
  `using static N.T;` and `using A = N.T;` in the file, then `global using` from any `.cs` file under
  the same nearest `.csproj` directory. `.csproj` `ProjectReference` is not read: code names
  namespaces, not projects.
- **Calls.** Locals; fields, properties and primary-constructor parameters with a declared type,
  which covers the 218 injected `_service` fields; `this.x`; `Type.M()` on a static; and an extension
  method called on a receiver of unknown type when exactly one extension method of that name is
  declared in a namespace the file imports.
- **Visibility.** `public`, `internal` and `protected internal` are exported, and so is a top-level
  type with no modifier, whose default is `internal`; a member with no modifier is `private`.
- **Attributes.** L8.

Corpus: `bonliva-crm-nx` (private).

### Razor

A component `Foo.razor` is `sym:<rel>::Foo`, exported, in the namespace `@namespace` names or, failing
that, the project's root namespace plus its folder path, as the Razor compiler assigns it. Its
`@code` and `@functions` members are `Foo.member`, read through the C# walk over the blanked copy
(L6). `@inject T Name` is a member with a declared type, so a call from `@code` resolves through it;
`@inherits` and `@implements` write `Extends`; `@using` joins the file's .NET usings, and an
`_Imports.razor` applies its usings to its directory and below. A markup tag `<Bar …>` whose name
resolves through the .NET index writes `Calls` from `Foo` to `Bar`: rendering a component is the
call. A code-behind `Foo.razor.cs` is a `partial class Foo` and resolves by C#'s partial rule. A `.csproj`
edit — a changed `RootNamespace`, a project added or removed — takes effect at the next `build`, not
on `update`: `update` widens by headers, and a project file declares none. Markup
expressions are not read. Corpus: `bonliva-crm-nx` `apps/bonliva-crm-timereport-web` (private).

### Rust

- **Module tree.** Each `Cargo.toml` in the repository gives a crate: its name with `-` read as `_`,
  and its roots `src/lib.rs`, `src/main.rs`, `src/bin/*.rs` and any `[lib] path`. `mod x;` names
  `x.rs` or `x/mod.rs` beside the declaring file; inline `mod x { … }` nests.
- **Items.** `fn`, `struct`, `enum`, `union`, `trait`, `type`, `const`, `static` and `macro_rules!`
  are symbols; trait methods are `Trait.method`.
- **`impl`.** Members of `impl T` or `impl Trait for T` are `sym:<rel>::T.m` in the file holding the
  `impl`. When that file does not declare `T`, it writes `References` to `T`'s resolved id, so `impact`
  on `T` reaches them. `impl Trait for T` writes `Extends` from `T` to `Trait` when both resolve.
- **`use`.** `crate::`, `self::`, `super::` and a workspace crate's name resolve through the module
  tree; braces, globs and `as` renames are read; an external crate resolves to nothing.
- **Calls.** Paths (`a::b::f()`, `T::new()`), locals, imported names, `self.field.m()` where the
  struct declares the field's type, and `name!(…)` for a `macro_rules!` the tree declares. A method
  on a receiver of unknown type is not resolved.
- **Visibility.** Any `pub`, `pub(crate)` included, is exported: a crate boundary is not a file
  boundary.

`#[cfg(test)]` modules are code and are read. Corpora: `repograph` itself (public) and
`agent-orchestrator`'s workspace.

### Python

A file's module name is its path from the nearest root, where the roots are the repository root,
every directory holding `pyproject.toml`, `setup.py` or `setup.cfg`, and the importing file's own
directory — a script's `sys.path[0]`, which is how every sibling import in the corpus resolves.
`import a.b` names `a/b.py` or `a/b/__init__.py`; `from a.b import c` names module `c` or name `c` in
`a.b`; `from .x import y` resolves by package. Symbols: `def`, `class` and module-level assignments to
plain names; methods and class-level assignments as `Class.member`; nested classes. An attribute's
type comes from an annotation or from `self.x = T(…)` in `__init__`. `Calls` through locals, imported
names, `module.f()`, `Class.m()` and `self.x.m()` with a known type. A leading underscore is not
exported; a module's `__all__`, when present, decides instead. The `if __name__ == "__main__":` body
declares nothing. Decorators: L8. Corpora: `repograph`'s `bench/` (public), `bonliva-erp`'s scripts
(private).

### Dart

A library is a file. `import 'package:name/path.dart'` names `lib/path.dart` under the directory whose
`pubspec.yaml` says `name: name`; relative imports name the file; `export` writes `ReExports`; `part`
and `part of` read as one library. Classes, mixins, extensions, enums, typedefs, top-level functions
and variables are symbols; members are `Type.member`; `extends`, `with` and `implements` write
`Extends`. `Calls` through locals, imported names and typed fields. A leading underscore is private.
Corpus: `pawfice` `app/lib` (Max's; a local repository with no remote).

### Swift

Declarations only: classes, structs, enums, protocols, functions and top-level constants, with an
`extension`'s members named on the extended type; an inheritance clause writes `Extends` when the name
resolves in the repository. No imports, because a Swift module sees every file in it, and no calls:
the only Swift is three written files of a Flutter runner, and there is nothing to measure a resolver
against. `private` and `fileprivate` are not exported. Corpus: `pawfice` `app/ios`.

### GraphQL

Operations are `sym:<rel>::query/Name`, `mutation/Name`, `subscription/Name`, and fragments
`fragment/Name`: GraphQL lets an operation and a type share a name. In schema documents, `type`,
`input`, `enum`, `interface`, `union`, `scalar` and `directive` definitions are symbols and fields are
`Type.field`. A spread `...Name` writes `Calls` to the fragment through the GraphQL index, which is
repository-wide because codegen treats fragment names as global; `on T`, variable types and field
types write `References` to a schema type the repository declares; `implements` writes `Extends`. No
TypeScript edge (L10). Corpus: `bonliva-crm-nx` `libs/graphql` and `apps/bonliva-crm-web` (private).

### SQL (PostgreSQL)

A statement walk over the grammar. `CREATE TABLE`, `VIEW`, `MATERIALIZED VIEW`, `FUNCTION`,
`PROCEDURE`, `TYPE`, `SCHEMA` and `SEQUENCE` are symbols, schema-qualified names joined with `/` (L4).
Columns from `CREATE TABLE` and `ALTER TABLE … ADD COLUMN`, and triggers, policies and indexes, are
members of their table: `clients.status`, `clients.audit_trigger`. Every file declaring or altering an
object is a declaring file (L3), so a table altered by eleven migrations resolves to twelve files.
`ALTER TABLE t` and `REFERENCES t` write `References`; `CREATE TRIGGER … EXECUTE FUNCTION f()` writes
`Calls` from the trigger to `f`; a view's `FROM` and `JOIN` write `References`. PL/pgSQL bodies are
dollar-quoted text and are not parsed; their text still reaches `ask`. Corpus: `beauty-crm`
`packages/db` (public).

### Bicep

`param`, `var`, `resource`, `module`, `type` and `func` are symbols by their symbolic name, and
`output/Name` for outputs, which have their own namespace. `module m './x.bicep'` writes `Imports` to
the file; a registry module (`br:`) resolves to nothing. A reference to another declaration's symbolic
name in the same file writes `References` from the declaration that holds it. Corpus: `bonliva-crm-nx`
`azure/` (private).

### HCL

Terraform addresses with `/` for `.` (L4): `aws_instance/web`, `data/aws_ami/ubuntu`, `var/region`,
`local/name`, `module/dns`, `output/ip`, `provider/hcloud`. A Terraform module is a directory, so
`var.x`, `local.x`, `module.m` and resource references in any `.tf` file resolve against declarations
in the same directory and write `References`; `module "m" { source = "./path" }` writes `Imports` to
every `.tf` file of that directory. Other HCL (`docker-bake.hcl`) reads its blocks by type and label —
`target/api`, `group/default`, `variable/TAG` — and `inherits` or `targets` lists write `References`.
Corpus: `beauty-crm` `infra/staging` (public).

### Shell

Function definitions are symbols, all exported. `source f` and `. f` write `Imports` for a literal
path and for a path built from the script's own directory — `"$(dirname "$0")/x"`,
`"${BASH_SOURCE%/*}/x"`, or a variable assigned one of those — and for nothing else. A command whose
name is a function declared in the file or a sourced file writes `Calls`. Running another script
(`bash x.sh`, `./x.sh`) writes `References` to its `file:` node. Corpora: `repograph`'s `bench/probe/`
(public), `bonliva-erp`'s scripts (private).

### Vue

The `<script>` block is read through the TypeScript walk over the blanked copy (L6), and the component
is `sym:<rel>::<FileStem>`, exported. The template is not read. Corpus: `customer-portal` (private).

## 8 · Shipping it

0.5.0 lost its release run to a `[skip ci]` in the squash body. GitHub skips a push-triggered
workflow when the pushed commit's message carries the marker anywhere, and a tag push is a push of
that commit. A squash merge copies every branch commit's message into the body, and the house
convention marks docs-only commits `[skip ci]`. Nothing failed and nothing ran; the release was
published by dispatching `release.yml` on the tag by hand, which publishes because the publish
steps test `startsWith(github.ref, 'refs/tags/')`.

A CI check that fails a PR carrying the marker would fight the convention on every docs commit, so
the fix is in the procedure, where the tag is made:

- **R1 · The release PR squashes with a written message.** The bump PR is merged with an explicit
  subject and body, not the concatenation GitHub offers.
- **R2 · The tagged commit is checked before its tag is pushed.** If
  `git log -1 --format=%B <sha>` matches `[skip ci]`, `[ci skip]`, `[no ci]`, `[skip actions]` or
  `[actions skip]`, the tag is pushed and `release.yml` is dispatched on it at once. Otherwise the tag
  is pushed and a `release` run for it must exist within two minutes, or it is dispatched then.
  Exactly one publishing run happens either way.
- **R3 · The binaries are proven before the number is spent.** `release.yml` dispatched from the
  branch builds, smokes and packs all three targets and publishes nothing. It runs on the release
  PR's head before the merge.
- **R4 · The bump.** `Cargo.toml`, `Cargo.lock`'s own entry, the `npm/*/package.json` files and the
  launcher's pinned optional dependencies, and the README status line, in the last PR before the
  tag.

`docs/bench/runbook.md` gains a release section holding R1 to R4 as commands.

## 9 · Decisions that are Max's

1. **Employer code's cases outside this repository** (§5), with aggregates published. The
   alternative is no Bonliva readings: C#, Razor, GraphQL, Bicep, Java and Vue would then ship on
   inline cases alone, which G6 exists to refuse.
2. **SQL through the PostgreSQL grammar**: +14.6 MB stripped, +0.8 MB compressed. The alternative is a
   statement scanner with no grammar — no size, and no independent truth, because the extractor and
   its truth reader would be the same regular expression.
3. **The waivers**: Swift without a `trace` case, Swift without a `changes` case if its history holds
   none, and any waiver a case task records. The alternative for Swift is to leave it files-only and save 3.7 MB
   stripped for three files.
4. **The bars**: 90% of `impact` files, every `trace`, every `changes` file and 90% of its symbols,
   ±5% declarations, one-file update ≤ 2× TypeScript's, +3.5 MB per archive. They can be changed in
   review, and not after the results document commits them.
5. **One release.** This design ships every language in 0.6.0, as asked, with each family merged to
   `main` behind an explicit glob so a slip holds only the defaults PR. The alternative is 0.6.0 with
   the layer, .NET, JVM and SQL, and the rest in 0.7.0.
6. **`enrich` producing nothing** exits 1, the same status as a missing store; moving it to 3 matches
   `trace` and `bench`. Not in the plans unless chosen.
7. **Spending.** G13 (the code seat), G14 (the register prompt), G28 (the reranked p90 bar), G37 (a
   non-Claude model) and G25 (int8 weights on the default model) each need tokens, a download or a
   decision about a shipped constant. None is in the plans. G32's ≈ $0.20 of haiku is.
