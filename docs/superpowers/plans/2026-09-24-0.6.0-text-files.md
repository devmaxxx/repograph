# 0.6.0 Every Text File Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every file the walk reads that is text and that no doc or code glob claims becomes one `Text` node whose text `ask` searches and whose path `changes` names, behind an empty `text_globs` default (#63, #69).

**Architecture:** A fourth walk class, `FileKind::Text`, decided by content (no NUL in the first 8,000 bytes) after registries, docs and code have had their say, and refused for lockfiles, bundles, maps, `vendor/` and anything over 1 MiB. Its extractor writes one `NodeKind::Text` node, id `file:<rel>`, whose body is the file's text. The lexical passage index already takes every kind but `File`, so the node is searchable with no filter change; the dense index cuts the body into rows the embedder reads whole. No edge leaves a text node.

**Tech Stack:** Rust 2021 (toolchain 1.98.0), `globset`, `ignore`, the bench kit under `bench/probe/`.

**Spec:** `docs/superpowers/specs/2026-09-11-0.6.0-languages-design.md` §11 (gates T1–T5). This plan replaces the master plan's Task 12T prose (`docs/superpowers/plans/2026-09-11-0.6.0-languages.md`), whose Global Constraints and measuring preamble apply here unchanged.

**Decision taken 2026-09-24 (Max):** a text file is a `NodeKind::Text` node, not a `File` node. `File` nodes are kept out of both passage indexes on purpose — a code file's node carries its head comment, and letting those in moved BM25 statistics before — so the kind is what tells the indexes a text file's body is meant for them. Task 1 amends the unread T2 clause to say so before any reading.

## Global Constraints

- Everything under the master plan's `## Global Constraints` applies, verbatim; this list only adds.
- Runs after master Task 11 has merged (so after Task 9's `REPOGRAPH_CODE_GLOBS`, which `REPOGRAPH_TEXT_GLOBS` copies), and before or beside the family plans: it touches no family's arm.
- One branch, `feat/0.6.0-text-files`, from `origin/main`; one draft PR; merged behind the empty default. Task 13 (#56) is where `text_globs` becomes `**/*`, if T5 lets it.
- `text_globs` empty ⇒ the walk, the graph and every index are byte-for-byte what they were (T1). Nothing in this plan changes a doc, code or registry entry's class.
- Binary is decided by content, as `git` decides: a NUL in the first 8,000 bytes. An extension never decides.
- Refused as text, and only as text: `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `poetry.lock`, `Gemfile.lock`, `composer.lock`, `go.sum`, `*.min.*`, `*.map`, `vendor/`. A text file over 1 MiB is skipped and counted. `skip` is unchanged.
- `REPOGRAPH_TEXT_GLOBS` behaves as `REPOGRAPH_CODE_GLOBS` does: whitespace-separated, replaces `text_globs` for one run, a blank value leaves the configured list, and a comma outside braces is refused by name (Max, 2026-09-24: a comma joins two globs into one that matches nothing). (The master plan's 12T prose said a blank value withdraws it; the spec says "as `REPOGRAPH_CODE_GLOBS` does", and the spec wins.)
- No text node is enriched: `enrich::eligible` and `eligible_code` stay as they are, so no spend follows the glob.

## Review Focus

1. A file whose first NUL sits after byte 8,000 is text, as `git` reads it, and is indexed — pinned in Task 4's walk case (`late.txt`).
2. A binary over 1 MiB is not counted as an oversized text file: the count names text left out, not every large file — pinned in Task 4's walk case (`big.png`).
3. A text file that grows past 1 MiB leaves the graph on the next update instead of lingering with its old body — Task 4's third case.
4. A text file with no line break (a one-line data blob under an unrefused name) is still cut into rows the embedder reads whole — Task 5's second case.
5. A lockfile or a `vendor/` tree below the root (`web/package-lock.json`, `web/vendor/…`) is refused as the root's would be — pinned in Task 4's walk case.

/// Refused as text whatever `text_globs` says: machine output nobody asks a question of, any one of
/// which would outweigh the hand-written files in the lexical index. Text entries only — `skip`
/// still decides for docs and code, so nothing already in the graph leaves it (spec §11, T1).
const TEXT_REFUSED: [&str; 11] = [
    "**/package-lock.json", "**/yarn.lock", "**/pnpm-lock.yaml", "**/Cargo.lock", "**/poetry.lock",
    "**/Gemfile.lock", "**/composer.lock", "**/go.sum", "**/*.min.*", "**/*.map", "**/vendor/**",

/// Over this a text file is data, not something written to be read, and is left out and counted.
pub const TEXT_MAX_BYTES: u64 = 1 << 20;

/// How far `git` looks for a NUL before calling a file binary.
const BINARY_PROBE: usize = 8_000;

fn binary(head: &[u8]) -> bool { head[..head.len().min(BINARY_PROBE)].contains(&0) }

/// Only the head is read: a binary over the limit is left out without being counted as text,
/// and without reading the rest of it.
fn binary_at(path: &Path) -> std::io::Result<bool> {
    use std::io::Read;
    let mut head = Vec::with_capacity(BINARY_PROBE);
    std::fs::File::open(path)?.take(BINARY_PROBE as u64).read_to_end(&mut head)?;
    Ok(binary(&head))
}
```

/// Under 256 tokens for the small model in Cyrillic, its densest script (about 2.5 chars a token).
const TEXT_ROW_CHARS: usize = 600;

fn text_rows(label: &str, body: &str) -> Vec<String> {
    let mut chunks = Vec::new();
    let (mut cur, mut len) = (String::new(), 0usize);
    for line in body.split_inclusive('\n') {
        for piece in pieces(line, TEXT_ROW_CHARS) {
            let n = piece.chars().count();
            if len + n > TEXT_ROW_CHARS && !cur.is_empty() {
                chunks.push(std::mem::take(&mut cur));
                len = 0;
            }
            cur.push_str(piece);
            len += n;
        }
    }
    chunks.push(cur);
    if chunks.iter().all(|c| c.trim().is_empty()) {
        return Vec::new();
    }
    chunks.into_iter().map(|c| format!("passage: {label}\n{c}")).collect()
}

/// `s` in runs of at most `n` chars, cut on char boundaries.
fn pieces(s: &str, n: usize) -> impl Iterator<Item = &str> {
    let mut rest = s;
    std::iter::from_fn(move || {
        if rest.is_empty() { return None; }
        let cut = rest.char_indices().nth(n).map_or(rest.len(), |(i, _)| i);
        let (head, tail) = rest.split_at(cut);
        rest = tail;
        Some(head)
    })
}
```

A blank chunk inside a file that has text elsewhere is kept, so the rows still concatenate back to the body (the first case's last assertion).
